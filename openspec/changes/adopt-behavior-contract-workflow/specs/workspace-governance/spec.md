## Purpose

保守担当者とコーディングエージェントが、変更の成果、利用者体験、確認深度を独立して判断し、永続的な振る舞い契約と実装を追跡できる変更運用を保証する。

## ADDED Requirements

### Requirement: 独立した変更運用の記録と追跡

リポジトリは、変更の運用区分、利用者体験への影響、確認深度を独立して記録し、観測可能な振る舞いまたは物質的構造を変える作業を OpenSpec Change と Scenario ID へ追跡できなければならない（MUST）。

#### Scenario: 振る舞いも物質的構造も変えない変更を記録する (WORKSPACE-GOVERNANCE-S023)

- **WHEN** 保守担当者が、変更理由とともに振る舞いも物質的構造も変えないことを記録する
- **THEN** リポジトリは OpenSpec Change と Scenario ID の理由付き非該当値を受理する
- **AND** 利用者体験への影響と確認深度を独立した値として保持する

#### Scenario: 契約または物質的構造を変える変更の追跡情報が不足する (WORKSPACE-GOVERNANCE-S024)

- **WHEN** 保守担当者が、観測可能な振る舞いまたは物質的構造を変える作業から OpenSpec Change または Scenario ID を省略する
- **THEN** リポジトリは変更記録を拒否する
- **AND** 不足している追跡情報を報告する

### Requirement: 意図と実装計画の境界

リポジトリは、提案が依頼の成果、制約、手段、根拠を解決するまで後続成果物を拒否し、永続的な設計と作業台帳へ実装時に決める詳細計画を固定してはならない（MUST）。

#### Scenario: 未解決の提案に後続成果物を追加する (WORKSPACE-GOVERNANCE-S025)

- **WHEN** 保守担当者が、重要な意図を未解決のまま仕様、設計、または作業台帳を追加する
- **THEN** リポジトリは後続成果物を拒否する
- **AND** 提案で解決が必要なことを報告する

#### Scenario: 作業台帳へ実装時に決める詳細計画を固定する (WORKSPACE-GOVERNANCE-S026)

- **WHEN** 保守担当者が、作業台帳をファイル、補助処理、または試験階層の単位へ細分化する
- **THEN** リポジトリは作業台帳を拒否する
- **AND** 成果単位の Work Package と客観的な完了証拠を要求する
